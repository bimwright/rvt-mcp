# v1.2.1 source validation and limits — 2026-10-20

This is a sanitized product validation summary for **unreleased 1.2.1 source**, not a published package or all-year native certification. Development assembly versions included a Git revision plus uncommitted changes; final clean-commit package identity and CI must be verified separately.

## Reproducible offline checks

From the repository root, with .NET 8/10 SDKs installed:

```powershell
dotnet test tests/RvtMcp.Tests/RvtMcp.Tests.csproj -c Release
dotnet run --project tests/RvtMcp.Settings.Tests -c Release
dotnet run --project tests/RvtMcp.Settings.Tests -c Release -- --model-picker-only
dotnet run --project tests/RvtMcp.Toast.Tests -c Release
22..27 | ForEach-Object {
    dotnet build "src/plugin-r$_/RvtMcp.Plugin.R$_.csproj" -c Release -p:RvtMcpSkipDeploy=true
    if ($LASTEXITCODE -ne 0) { throw "Plugin build failed for R$_" }
}
```

The WPF executables require an interactive Windows session. Skip-deploy is mandatory when building while Revit is running; these commands do not install add-ins or edit a live model.

Covered source checks include:

- Warning policy defaults, invalid values, JSON/env/CLI precedence and per-call propagation without freezing later Settings edits.
- Production failure-processing/record/receipt methods against native API doubles and disposable SQLite, including incident-write failure before acknowledgment.
- Real Settings window/adapter with disposable configuration: Apply/Discard/reopen, failed save/retry, host overrides, rendered journal presets through 14d and actual expiry.
- History decision scope/revision constraints, shared placeholder/icon behavior, stable picker widths/navigation and copied source preservation.
- Send-code ownership/cleanup rules, valid conditional source syntax and explicit tracking of unsupported automatic-instrumentation forms.
- Accepted-warning summary text versus actual rollback, including a rule decision made after the original rollback.
- Complete localization catalogs and multi-target compilation for Revit 2022–2027.

A default-parallel full-suite run passed **2,491 tests** after the pre-commit conditional-source and summary-text corrections (the earlier source had 2,480 tests). Other parallel attempts, including a staged backend-only snapshot (2,476 passed / 1 failed), had five-second background-worker timeouts. The unchanged backend rerun passed 2,477 tests; the staged UI/source snapshot passed all 2,491 tests with default parallelism, along with full WPF Settings/History, picker and toast checks. No worker, timeout or global parallel setting was changed. A temporary pool diagnostic saw queued work but did not reproduce the failure or establish its cause; that instrumentation was removed. The later green runs do not claim the intermittent timeout fixed. Final source/CI results must be evaluated without treating a serial run as proof of parallel reliability. The existing `xUnit1031` analyzer warning also remains separate from plugin build warnings.

## Scoped native Revit 2026 checks

A matching 1.2.1 development gateway assembly and add-in were used with a new unsaved test project. The production gateway entry point ran through a disposable-config test launcher; fresh initialize, tool schema/runtime metadata and host identity were checked. This was not the final self-contained Setup executable or a client installation upgrade.

| Scenario | Native observation |
|---|---|
| Default policy, complete Warning | Transaction rolled back; test marker absent; complete incident retained. |
| Explicit accept-and-log, complete Warning | Transaction committed; marker present; complete `accepted_by_policy` incident and receipt; no rule/grant consumed. |
| Error under accept-and-log | Transaction rolled back; marker absent; Error incident retained. |
| Incomplete before-capture in a newly created background document | Warning transaction rolled back, not policy-accepted; background fixture closed without saving. |
| Actual coincident-wall warning, opt-in | Transaction committed and both failing wall IDs recorded completely as `accepted_by_policy`. |
| Actual coincident-wall warnings, default | Transaction rolled back; newly created test elements absent. |
| Controlled incident-write failure, opt-in | Transaction rolled back before acknowledgment; receipt reported persistence failure and review required. |
| Normal write after recorded failures | A later transaction committed; historical review findings did not impose a permanent write gate. |

The persistence-fault case temporarily routed the native callback to a **private SQLite snapshot** in `try/finally`; a trigger rejected incident inserts only in that copy. The original store was restored, and the live shared ledger did not receive the trigger.

The wall test initially had a harness count assertion that assumed three new elements. Native changes reported four, including an auxiliary element. The existing native result and complete ledger record were audited without replaying the committed mutation; the original assertion failure was retained rather than relabeled as an initially green run.

Only owned test elements were removed afterward, restoring the fixture's baseline element count. The test project remained unsaved/open; owner configuration and unrelated Revit models were not changed. Raw local models, Autodesk catalogue text, machine identifiers and private test artifacts are not part of this public summary.

## Boundaries still open

- Native policy evidence is scoped to Revit 2026 development assemblies. Builds for 2022–2027 do not certify every native year or final package bytes.
- DocumentCorruption was not injected into native Revit. Corruption/truncation boundaries have offline regression evidence; do not claim native corruption acceptance.
- A rollback of the tested transaction is not always a whole-call rollback: creating a background document can include earlier template initialization commits, producing a `partial` operation receipt even after fixture cleanup.
- Native persistence fault injection used an isolated snapshot, not an outage/corruption of the owner's real ledger.
- Save As, save-on-close, central upgrades, delayed reminders, every dialog adapter and Revit 2026 rebar creation need their own native acceptance scope.
- The previous family-load/recovery-dialog crash is not claimed fixed. Lifecycle cleanup checks do not establish recovery from arbitrary native crashes.
- Final clean-source CI, Setup/MCPB/NuGet packaging and client reconnect/installation verification remain separate release tasks.
